 1. この2つのファイルは何なのか
================================================================

  プロジェクトのいちばん上のフォルダに、
  「.gitignore」と「.gitattributes」という2つのファイルが
  あります。名前が「.」から始まるので、PC の設定によっては
  見えないかもしれません。

  この2つは、Git（ギット）という、みんなの作業を1つに
  まとめる仕組みへの「指示書」です。

  例えるなら、引っ越し業者に渡すメモのようなものです。

    ■ .gitignore
        役割 : 何を運ばないかを決める
        例え : 「このゴミ袋は持っていかないで」

    ■ .gitattributes
        役割 : どう運ぶかを決める
        例え : 「この箱は割れ物。専用の梱包で」

  どちらも自動で効くので、普段は存在を意識しなくて
  大丈夫です。ただ、たまに「あれ？」という現象の原因に
  なるので、その時にこの文書へ戻ってきてください。


================================================================
 2. .gitignore  ―  「これは共有しなくていい」リスト
================================================================

----------------------------------------------------------------
 2-1. なぜ必要か
----------------------------------------------------------------

  Unity のプロジェクトフォルダの中には、大きく分けて
  2種類のファイルがあります。

    ・原本
        あなたが作ったもの。3Dモデル、テクスチャ、音声、
        シーン、スクリプト、設定。

    ・一時ファイル
        Unity が原本から「自動で作り直せる」もの。

  後者の代表が「Library」フォルダです。プロジェクトを開く
  たびに Unity が作るキャッシュで、数 GB になることも
  ザラです。これを共有してしまうと、

    ・保管場所が何十 GB にも膨れ上がる
    ・全員のマシンで中身が微妙に違うので、
      毎回「変更あり」と出続ける
    ・他人の Library を受け取ると、かえって Unity が壊れる

  という三重苦になります。だから .gitignore に書いて、
  最初から共有対象から外しています。

  ────────────────────────────────────────────────
   ヒント：「Corrupted Library Detected」が出たら
  ────────────────────────────────────────────────
   Library が壊れただけです。「Rebuild Library」を
   押せば作り直されます。共有していないので、
   誰にも迷惑はかかりません。安心して押してください。
  ────────────────────────────────────────────────

----------------------------------------------------------------
 2-2. 主に何を外しているか
----------------------------------------------------------------

  ■ Unity の自動生成物
      例   : Library/  Temp/  Logs/  obj/
      理由 : 開くたびに作り直される

  ■ ビルド成果物
      例   : Build/  *.apk  *.aab  *.ipa  *.app
      理由 : 巨大。必要なら別途配布する

  ■ IDE の個人設定
      例   : .idea/  .vs/  *.csproj  *.sln
      理由 : 人によって違って当然のもの

  ■ OS のゴミファイル
      例   : .DS_Store（Mac）  Thumbs.db（Windows）
      理由 : 中身に意味がない

  ■ 鍵・パスワード類
      例   : *.keystore  *.jks  .env
      理由 : 漏れると事故になる

----------------------------------------------------------------
 2-3. 【重要】絶対にコミットしてはいけないもの
----------------------------------------------------------------

  .gitignore は防波堤ですが、完璧ではありません。
  以下は人間側でも気をつけてください。

    ・アプリの署名鍵
      （.keystore / .jks / .p12 / .mobileprovision）
    ・API キー、パスワード、アクセストークンが
      書かれたテキスト
    ・契約上、社外に出せない支給素材

  とくに Android の署名鍵は、漏れると偽アプリを
  作られてしまいます。絶対に共有リポジトリへ入れないで
  ください。鍵の受け渡しはリーダーに相談してください。

  ────────────────────────────────────────────────
   ★ Unity の落とし穴
  ────────────────────────────────────────────────
   Unity でキーストアのパスワードを入力し「記憶する」に
   すると、ProjectSettings/ProjectSettings.asset という
   ファイルに、パスワードがそのままの文字で
   書き込まれます。

   このファイルは共有必須なので .gitignore では
   防げません。

   → キーストアのパスワードは Unity に保存させず、
     ビルドのたびに入力してください。
  ────────────────────────────────────────────────

----------------------------------------------------------------
 2-4. よくある困りごと：「作ったファイルが共有されない」
----------------------------------------------------------------

  .gitignore に該当するファイルは、Git 上で
  「存在しないもの」扱いになります。意図せず引っかかる
  ことがあります。

  確認方法（自分で叩いても安全です）:

      git check-ignore -v 共有されないファイルのパス

  何か表示されたら、それが除外している行です。
  何も表示されなければ .gitignore は無関係で、
  別の原因（コミットし忘れなど）です。


================================================================
 3. .gitattributes  ―  「このファイルはこう扱って」
================================================================

  こちらは3つの仕事をしています。
  非エンジニアの方に影響が大きいのは 3-1 と 3-3 です。

----------------------------------------------------------------
 3-1. 大きなファイルを Git LFS で運ぶ 【重要】
----------------------------------------------------------------

  ● Git LFS とは

  Git はもともと「テキスト（文字）を管理する道具」で、
  画像や音声のような大きなファイルが苦手です。
  1枚のテクスチャを10回描き直すと、そのまま10枚分の
  容量が永久に積み上がります。

  そこで Git LFS（Large File Storage）という拡張を
  使います。大きなファイルは別の倉庫に預け、Git には
  「預かり証」だけを置く仕組みです。

  .gitattributes には「どの拡張子を LFS 送りにするか」が
  書いてあります。

    画像           : .png .psd .psb .tga .exr .dds .ktx2
    3Dモデル       : .fbx .blend .obj .glb .gltf .abc .usd
    音声           : .wav .mp3 .ogg .aiff .flac
    動画           : .mp4 .mov .webm
    フォント       : .ttf .otf .ttc .woff2
    プラグイン     : .dll .so .dylib .aar .framework .bundle
    AIモデル       : .onnx .sentis

  新しい素材を追加するときに、あなたが何かする必要は
  ありません。拡張子を見て自動的に振り分けられます。


  ● 【必須】git lfs install

  LFS は、各自の PC で1回セットアップしないと機能しません。
  やらないまま作業すると、素材が壊れた状態で共有されて
  しまい、全員に影響が出ます。

      git lfs install

  PC 1台につき1回だけ。すでに実行済みでも、
  もう一度打って害はありません。


  ● 症状：画像が真っ白 / Unity で素材が読めない

  LFS の実体が手元に落ちてきていない状態です。
  テクスチャをメモ帳で開くと、こんな3行になっています。

      version https://git-lfs.github.com/spec/v1
      oid sha256:4d7a2...
      size 1048576

  これは「預かり証」だけの状態です。
  次のコマンドで実体を取ってきてください。

      git lfs pull

----------------------------------------------------------------
 3-2. 改行コードを揃える
----------------------------------------------------------------

  Windows と Mac では「改行」の記録方法が違います
  （CRLF と LF）。放っておくと、中身を一文字も変えて
  いないのに「全行変更しました」と表示される現象が
  起きます。

  レビューが不可能になるので、.gitattributes で
  全員 LF に統一しています。自動で処理されるので、
  意識する必要はありません。

----------------------------------------------------------------
 3-3. シーンや Prefab のコンフリクト対策
----------------------------------------------------------------

  ● コンフリクトとは

  2人が同じファイルの同じ場所を同時に変更すると、
  Git は「どっちが正しいか分かりません」と手を止めます。
  これがコンフリクト（衝突）です。

  Unity のシーンや Prefab は、中身が人間には読みづらい
  形式で保存されているため、これが起きると手作業での
  解決がほぼ不可能です。

  そこで Unity 公式の SmartMerge（UnityYAMLMerge）という
  専用ツールを使う設定を .gitattributes に書いています。
  「A さんはライトを動かした、B さんは別のオブジェクトを
  追加した」程度なら、これが自動で両方を取り込みます。


  ● 【必須】各自の設定が必要です

  .gitattributes は「SmartMerge を使え」と指示している
  だけで、ツールの場所を各 PC に教えてあげないと
  動きません。4章③ の手順をやってください。


  ● それでも運用ルールは必要です

  SmartMerge は万能ではありません。同じオブジェクトの
  同じ値を2人が変えた場合は、やはり手作業になります。

    ・シーンや Prefab を触る前に、Slack などで一声かける
    ・作業前に必ず最新を取得（git pull）する
    ・大きなシーンは分割するか、作業を時間でずらす


================================================================
 4. 初回セットアップ手順
================================================================

  新しく参加した方・PC を入れ替えた方は、
  これを上から順にやってください。

----------------------------------------------------------------
 ① Git LFS を有効化する
----------------------------------------------------------------

      git lfs install

----------------------------------------------------------------
 ② プロジェクトを取得する
----------------------------------------------------------------

      git clone <リポジトリのURL>
      cd <プロジェクトフォルダ>
      git lfs pull

----------------------------------------------------------------
 ③ Unity SmartMerge を登録する
----------------------------------------------------------------

  <version> は実際の Unity バージョン
  （例: 6000.3.0f1）に置き換えてください。

  ▼ Windows の場合（3行とも実行）

    git config --global merge.unityyamlmerge.name "Unity SmartMerge"

    git config --global merge.unityyamlmerge.driver '"C:/Program Files/Unity/Hub/Editor/<version>/Editor/Data/Tools/UnityYAMLMerge.exe" merge -p --force --fallback none %O %B %A %A'

    git config --global merge.unityyamlmerge.recursive binary

  ▼ Mac の場合（3行とも実行）

    git config --global merge.unityyamlmerge.name "Unity SmartMerge"

    git config --global merge.unityyamlmerge.driver '"/Applications/Unity/Hub/Editor/<version>/Unity.app/Contents/Tools/UnityYAMLMerge" merge -p --force --fallback none %O %B %A %A'

    git config --global merge.unityyamlmerge.recursive binary

  パスが分からない場合は、Unity Hub で該当バージョンの
  歯車マーク →「インストール場所を表示」から辿れます。
  うまくいかなければエンジニアに聞いてください。

----------------------------------------------------------------
 ④ Unity 側の設定を確認する
----------------------------------------------------------------

  Edit → Project Settings → Editor を開いて、
  以下になっているか確認します。

      Version Control → Mode
          … Visible Meta Files

      Asset Serialization → Mode
          … Force Text

  これが違っていると、SmartMerge も差分表示も
  機能しません。通常はプロジェクト側で設定済みなので、
  勝手に変更せず、違っていたら報告してください。

 5. 日常のルール
================================================================

----------------------------------------------------------------
 ○ やってください
----------------------------------------------------------------

  ・作業を始める前に git pull で最新にする
  ・シーン、Prefab を触るときは事前に共有する
  ・素材を追加したら、.meta ファイルも
    必ず一緒にコミットする
  ・コミット前に「何が含まれるか」を一度確認する

----------------------------------------------------------------
 × 避けてください
----------------------------------------------------------------

  ・.gitignore / .gitattributes を独断で編集する
    （→ 6章へ）

  ・git add -f（強制追加）を、意味が分からないまま使う

  ・プロジェクトフォルダを
    OneDrive / Dropbox / iCloud の同期対象に置く
      → Git と同期ソフトが喧嘩して Library や .git が
        壊れます。ローカルディスクに置いてください。

  ・Library / Temp フォルダを手動でいじる


================================================================
 6. ファイルを編集したくなったら
================================================================

  「この拡張子が LFS に入っていない」
  「このフォルダを除外したい」と思ったら、
  自分で書き換えず、エンジニアに相談してください。
  理由は2つあります。

    1. .gitattributes の書き方は罠が多く、
       一見正しく見えて「まったく効いていない」
       ということが頻繁に起きます。

    2. すでにコミット済みのファイルは、ルールを後から
       足しても過去の分は変わりません。
       履歴の作り直しという大掛かりな作業が必要です。

----------------------------------------------------------------
 ファイル内の構造について
----------------------------------------------------------------

  両ファイルとも、途中にこのような区切りがあります。

    # ==========================================
    #  ここから下はプロジェクト固有の追記
    #  （上のテンプレート部分は ... 再同期できるよう
    #    触らずに残しておくこと）
    # ==========================================

  ・区切りより上
      Unity 公式コミュニティのテンプレート。
      将来まとめて更新できるよう、1文字も変えていません。

  ・区切りより下
      このプロジェクト独自の追記。
      変更するならこちら側です。


================================================================
 7. 困ったときは
================================================================

  ■ 「Corrupted Library Detected」が出る
      原因 : Library キャッシュの破損
      対処 : 「Rebuild Library」を押す。
             直らなければ Unity を閉じて
             Library フォルダを削除

  ■ 画像・モデルが真っ白 / 読み込めない
      原因 : LFS の実体が未取得
      対処 : git lfs pull

  ■ コミットしたのに他の人に見えない
      原因 : .gitignore で除外されている
      対処 : git check-ignore -v <パス> で確認

  ■ 何も変えていないのに全行が変更扱い
      原因 : 改行コードの不一致
      対処 : .gitattributes が効いていない。
             エンジニアに相談

  ■ シーンのコンフリクトが解決できない
      原因 : SmartMerge 未設定、または同一箇所の競合
      対処 : 4章③ を確認。それでもダメなら
             片方の変更を採用してやり直す

  ■ Unity でアセットが「?」アイコンになる
      原因 : .meta ファイルがコミットされていない
      対処 : .meta を含めてコミットし直す

  上記で解決しない場合は、自己流で復旧を試みる前に、
  エラーメッセージのスクリーンショットを添えて
  相談してください。中途半端に直そうとしたほうが、
  傷が深くなることがあります。


================================================================
 8. 用語集
================================================================

  ■ リポジトリ
      プロジェクトの共有保管庫。履歴もすべて入っている

  ■ コミット
      変更に名前を付けて記録すること。セーブポイント

  ■ プッシュ / プル
      手元の記録を共有先へ送る /
      共有先の記録を手元に取り込む

  ■ コンフリクト
      2人の変更が衝突して、Git が自動判断できない状態

  ■ LFS
      大きなファイルを別倉庫に預ける仕組み

  ■ バイナリ
      画像や音声など、文字として読めない形式のファイル

  ■ .meta
      Unity が素材ごとに作る設定ファイル。
      素材本体とセットで必須

  ■ YAML
      シーンや Prefab の保存形式。
      テキストだが人間には読みづらい
